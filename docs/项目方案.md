## 1. 目标与非目标

### 1.1 目标

| 目标 | 判定标准 |
|------|----------|
| 「克隆即开工」的 Wails v3 模板 | `pnpm dev` 一条命令起；三平台 `wails3 task <os>:package` 可出安装包 |
| **Vite Plus 作为唯一前端工具链** | dev / build / lint / fmt / check 全部走 `vp`，不引入标准 vite 作为备胎 |
| 依赖一律取**实测最新版**，官方指定优先 | 版本决策表给出实测号、官方约束、采用值与理由 |
| 与 electron-template 对齐的工程成熟度 | 安全基线、质量门禁、镜像策略、提交规范、示例页、文档 |
| 契约「只有一份来源」 | Go 结构体 + 生成 bindings 为唯一契约，前端不写重复 DTO |

### 1.2 非目标

| 不做 | 原因 |
|------|------|
| iOS / Android | v3 移动端仍为 experimental（官方模板仍生成 `build/ios`、`build/android`；本模板已删除两者） |
| Server 模式产品化 | 保留 Taskfile 任务即可 |
| 自动更新通道运营 | 计划只留 `app.Updater` 接入点与签名校验位；当前实现未接入 |
| 改 electron-template | 只读参考 |

**为此换掉的依赖：零。** 只做了三件“配置级”调整：

1. 显式声明 `vite` 别名（否则 `vp` 无法解析配置依赖）；
2. TS 由 7.0.2 降到 6.0.3（vue-tsc 硬约束）；
3. 在仓库级配置里加 `lint.ignorePatterns` / `fmt` 规则并排除 `bindings/**`、`dist/**`、`node_modules/**`。

### 3.4 附带结论（写进模板配置规范）

```ts
// 仓库级 vite.config.ts（只被 vp lint/fmt/staged 读取，与 electron-template 同款结构）
import { defineConfig } from "vite-plus"
export default defineConfig({
  fmt: { semi: false, singleQuote: true, printWidth: 140, trailingComma: "all", endOfLine: "lf" },
  lint: { ignorePatterns: ["dist/**", "bindings/**", "node_modules/**", "**/node_modules/**"] },
  staged: { "*.{ts,tsx,vue,json,md,yml,yaml}": "vp check --fix" },
})
```

- `bindings/**` 必须排除在 fmt/lint 之外：它是生成物，被格式化会导致每次重生成都产生 diff（破坏 §5.3 的漂移检测）。
- `vp build` 是内置命令；若要在 npm script 里跑同名脚本用 `vpr build`（CLI 会提示这一条）。
- `vp` 另有 `vp migrate`（把标准 vite 工程迁到 Vite Plus）、`vp check`（fmt + lint + 类型检查合并）、`vp staged`（暂存区检查），可直接作为质量门禁入口。
- `vp build` 启动时会做 `Verifying lockfile against supply-chain policies` 校验（实测输出），等于自带一层依赖安全闸门。

## 5. 分层与边界

### 5.1 三层

```
前端 views/stores → bridge/（错误归一化 + 超时 + 取消）→ 生成 bindings → service（Go）
                                                   ↗ 具名事件 Events（后端→前端）
```

| 层 | 允许 | 禁止 |
|----|------|------|
| views/stores | UI、状态、i18n、经 bridge 调用 | 直接 import 具体服务文件 |
| bridge | 错误映射、超时、取消、DTO 再导出 | 复制 DTO 定义 |
| bindings | 无（生成） | 手改；被 fmt 重排 |

### 5.2 类型单一来源

**结论：只保留生成契约（方案 B），不维护手写 DTO。**

- 服务 public 方法 = 前端可调用面；DTO 只在 Go 定义（带 `json` tag + 注释，生成器会把注释和参数名带到 TS）。
- 事件用 `application.RegisterEvent[T]("x")` 获得强类型事件名。
- `-obfuscated` 构建需配 `Options.BindAliases` 固定 ID；日常构建不开。
- **实测踩坑（必须写进模板规范）**：`bindings/<pkg>/index.ts` 不 re-export 服务方法，前端要 `import { Greet } from "bindings/<pkg>/greetservice"`；把这条写进 `bridge/` 的导出约定里，避免每个页面各自猜路径。

### 5.3 生成产物入库 + CI 防漂移

| 决策 | 结论 |
|------|------|
| 入库 | ✅ `packages/frontend/bindings/**` 进版本库（契约 diff 可评审；纯前端 clone 也能看类型） |
| 刷新 | `build:frontend` 的 deps 已含 `generate:bindings`（`sources` 覆盖 `**/*.go`、`go.mod`、`go.sum`） |
| 防漂移 | CI：`wails3 generate bindings -ts -i -clean` → `git diff --exit-code -- packages/frontend/bindings` |
| 禁止 | `bindings/**` 不进 fmt/lint 范围（否则 diff 抖动，检测失效） |

## 9. 开发体验

### 9.1 热重载链路（实测自模板配置）

```
wails3 dev -config ./build/config.yml -port <N>
  ├─ 校验端口（占用即退出，不递增）
  ├─ 导出 WAILS_VITE_PORT / FRONTEND_DEVSERVER_URL
  └─ dev_mode.executes：
       ├─ blocking  : wails3 build DEV=true      → 走 build:frontend → `pnpm run build:dev`（vp build）
       ├─ background: wails3 task common:dev:frontend → `pnpm run dev -- --port N --strictPort`（vp dev）
       └─ primary   : wails3 task run（等待 dev server HTTP 200，上限 60s）
```

| 改动 | 生效 |
|------|------|
| `packages/frontend/src/**` | `vp dev` HMR（`dev_mode.ignore.dir` 已排除 `frontend`，不会被 Go watcher 干扰） |
| `*.go` | watcher（`watched_extension: *.go/*.js/*.ts`，`debounce 1000`）→ 重新 `wails3 build DEV=true` → 重启 |
| `build/config.yml`、Taskfile | 手动重启 `wails3 dev` |

**验证过的关键点**：官方 Taskfile 的 `pnpm run dev -- --port N --strictPort` 在 `vp dev` 下正常工作（端口 9299 实测），因此**不需要改 Taskfile 的 dev 分支**。

### 9.2 端口策略

| 项 | electron-template | 本模板 |
|----|-------------------|--------|
| 选择 | `scripts/dev.mjs` 从 5173 递增探测 | `wails3 dev` 固定 9245、占用即失败 → 由 `scripts/dev.mjs` 先探测 9245–9255 取空闲，再 `wails3 dev -port N` |
| 防漂移 | `strictPort` | `strictPort: true`（模板 vite.config 已带，`vp dev` 同样接受该参数） |
| 就绪 | 轮询 2xx，90s | 框架 60s HTTP 200 就绪检查 |

### 9.3 日志

| 项 | 做法 |

## 10. 构建与打包

### 10.1 `vp build` 与 `wails3 build` 的关系（顺序固定）

```
wails3 build [DEV=true]
  └─ task build → <os>:build
       └─ build:frontend（deps: install:frontend:deps + generate:bindings）
            ├─ 生成 bindings：wails3 generate bindings -ts -i -clean
            ├─ 前端构建：pnpm run build（生产）/ pnpm run build:dev（DEV=true）
            │     └─ 脚本内：vue-tsc --noEmit && vp build
            └─ go build + embed packages/frontend/dist
```

**规则**：`vp build` 永远只在前端脚本里被间接调用，不单独对项目根跑；产物 `packages/frontend/dist` 被 `//go:embed all:packages/frontend/dist` 打进二进制。前端脚本名必须是 `build` / `build:dev`（Taskfile 硬编码），否则打包会静默取不到产物。

### 10.2 三平台产物

| 平台 | 命令 | 产物 |
|------|------|------|
| macOS | `wails3 task darwin:package:dmg` / `darwin:package:universal` | `.app` / `.dmg` |
| Windows | `wails3 task windows:package`（`FORMAT=msix` 可切） | NSIS 安装包（脚本 `build/windows/nsis/project.nsi` 可改）/ `.msix` |
| Linux | `wails3 task linux:package` | AppImage / deb / rpm / Arch（nfpm 配置 `build/linux/nfpm/nfpm.yaml`） |
| 交叉 | `wails3 task setup:docker` + `GOOS=` 系列 | Docker 镜像内产出 |

命名规范沿用 v1：`<产品名>-<版本>-<os>-<arch>.<ext>`，由 `scripts/rename-artifacts.mjs` 后处理。

### 10.3 元数据与图标
